# ระบบติดตามคำร้องขอฝากขัง (ทางจอภาพ) — ศาลจังหวัดอุดรธานี

**เริ่มอ่านที่ `SPEC.md` ก่อนเสมอ** — เอกสารนั้นสรุปทุกข้อกำหนด/การตัดสินใจออกแบบที่คุยกับเจ้าของระบบ
(ศาลจังหวัดอุดรธานี) จนได้ข้อสรุปแล้วทั้งหมด รวมถึงฐานกฎหมาย, สิทธิ์ผู้ใช้แต่ละบทบาท, flow การทำงานเต็ม,
จุดอ่อนที่ตรวจพบและแก้ไขแล้ว, และสิ่งที่ยังไม่ได้ทำ/ต้องตัดสินใจเพิ่ม — README นี้พูดแค่เรื่องโครงสร้างไฟล์
กับวิธีรันเทสต์เท่านั้น

## โครงสร้างโปรเจกต์

```
udon-remand-system/
├── SPEC.md                    ← อ่านก่อนไฟล์อื่นเสมอ
├── udon-remand-tracker.html   ← เดโมพร้อมรัน ไม่ต้อง build เลย เปิดไฟล์ตรงๆ หรือวางบน Vercel เป็น static site ได้ทันที (ทดสอบแล้วว่ารันได้จริง ไม่มี error)
├── demo/
│   └── udon-remand-tracker.jsx   ← ซอร์สโค้ด React ต้นฉบับ (ES module) สำหรับ import เข้าโปรเจกต์ Next.js จริง
├── lib/
│   ├── legalLogic.js          ← ตรรกะกฎหมายล้วนๆ (วันที่, เพดาน, เวลาตัด, ตรวจไฟล์อัพโหลด)
│   ├── legalLogic.test.js
│   ├── caseEngine.js          ← ชั้นต่อยอด: นำกฎหมายมาใช้กับ object คดีจริง (UI ควรเรียกใช้ชั้นนี้)
│   ├── caseEngine.test.js     ← รวม simulation คดีเต็มเพดาน + เคสขอบ (อัพโหลดผิดคดี, คืนสำนวน, ฯลฯ)
│   ├── icsFeed.js             ← ตัวสร้างไฟล์ปฏิทิน .ics (สำหรับ URL สมัครรับปฏิทินฝั่งตำรวจ)
│   └── icsFeed.test.js
├── package.json               ← รัน `npm test` ได้เลย
└── README.md (ไฟล์นี้)
```

## หลักการออกแบบ

- **`legalLogic.js`** = กฎหมาย/ระเบียบล้วนๆ ไม่รู้จัก "คดี" คืออะไร รู้แค่วันที่กับตัวเลข
- **`caseEngine.js`** = เอากฎหมายมาใช้กับคดีจริง (object ที่มี state, ประวัติ) — นี่คือชั้นที่ UI ควรเรียก
- **UI (React)** = แสดงผล + รับ input เท่านั้น ไม่ควรมีตรรกะกฎหมายฝังอยู่เลยในระยะยาว

แยกแบบนี้เพื่อ: (1) แก้กฎหมายใหม่แก้ที่เดียว (2) ทดสอบอัตโนมัติได้จริง (3) คนอื่นต่อยอดได้โดยไม่ต้องอ่าน React

## หมายเหตุสำคัญเรื่องไฟล์เดโม `.jsx` และ `.html`

มี 2 เวอร์ชันของเดโมเดียวกัน หน้าตา/ฟีเจอร์เหมือนกันทุกอย่าง ต่างกันแค่วิธี run:

- **`udon-remand-tracker.html`** (ไฟล์เดี่ยว รันได้ทันที) — เปิดตรงๆ จากเครื่อง หรือวางบน Vercel เป็น static site ได้เลย ไม่ต้องมีขั้นตอน build/npm install ใดๆ **ทดสอบแล้วว่ารันได้จริงไม่มี error** (ใช้ React/ReactDOM แบบ UMD + Babel Standalone แปลง JSX สดในเบราว์เซอร์ + ไอคอนฝังในตัวไฟล์เลยไม่ต้องพึ่ง lucide-react จาก CDN ภายนอก) — **เหมาะใช้ตอนนี้เพื่อรีวิว/ทดสอบ UI และตรรกะ** ก่อนเริ่มสร้าง Next.js จริง
- **`demo/udon-remand-tracker.jsx`** (ซอร์สโค้ด ES module ปกติ) — รันในสภาพแวดล้อมพรีวิวไฟล์เดียวของแชท **ไม่สามารถ import จาก `lib/` เข้าไปได้จริง** (ข้อจำกัดของเครื่องมือพรีวิว ไม่ใช่ของโค้ด) จึงมีตรรกะ/ฟังก์ชันจัดการบัญชี-เลขคดีบางส่วนอยู่ในไฟล์นี้โดยตรง แทนที่จะ import จาก `lib/caseEngine.js` — ตอนสร้างโปรเจกต์ Next.js จริง **ให้เริ่มจากไฟล์นี้** (ไม่ใช่ `.html`) แล้วเปลี่ยนให้ import จาก `lib/caseEngine.js` โดยตรงแทน ลบสำเนาที่ซ้ำทิ้งได้เลย รายละเอียดว่าฟังก์ชันไหนอยู่ตรงไหนดู SPEC.md ข้อ 8
